# Source-only CI build of `tree_of_md`

The canonical public converter is **`tree_of_md`**. The package/repository remains
`tree-md`; the legacy executable and the existing `bin/public_main.ml` Dune
entrypoint are unchanged. This driver is not a publisher or a Forester renderer.
It reads no snapshot, vault, attachments, deployment configuration or credentials.

## Fixed build contract

After the caller has checked out and validated an immutable, trusted converter
revision (including these driver/flake files), run from that checkout:

```sh
nix develop --no-write-lock-file --command python3 scripts/build-public-cli.py
```

The exact converter build argument array, once the reviewed source revision
exists, is:

```json
[
  "nix", "develop", "--no-write-lock-file", "--command", "python3",
  "scripts/build-public-cli.py"
]
```

The converter executable value is `_build/public-cli/tree_of_md`. Use these values
in the caller's existing pin schema together with the **reviewed full source
commit**; this document does not define or update that schema.

These are argument arrays, not content-supplied shell commands. The driver accepts
no arguments and issues no Git command. Revision validation, snapshot approval,
expected snapshot digest and converter SHA-256 verification belong to the caller.
Do not replace an immutable revision pin with a branch name or a development
worktree. Nothing in this change updates CI, remote repositories or deployments.

`flake.lock` is generated by real `nix flake lock`. Its nixpkgs input is
`70ce234312134a463ba7728e94da2486a1d237ac`, also the existing converter Devbox Dune
pin. The environment supplies Dune **3.23.1**, make, Git, pkg-config, libyaml,
Python, autoconf, automake and patch, plus the normal `mkShell` C toolchain.
It does **not** provide an OCaml switch or re-solve dependencies. The existing
`dune-workspace` and `dune.lock` supply the converter's OCaml **5.3.0** compiler
and exact dependency sources/checksums. No `dune pkg lock`, Opam installation,
`devbox run` or floating package lookup is used. The separate Forester 6 renderer
may require OCaml 5.4 or newer; that is not a reason to change this converter lock.

## Fresh source build and regular artifact

The driver validates regular, nonsymlink build inputs and copies only:

- `dune-project`, `dune-workspace`, `tree-md.opam`;
- `bin/` and `lib/`: Dune files and OCaml sources/interfaces;
- the existing `dune.lock/`: `lock.dune` and locked package files.

A fresh, exclusive `_build/public-cli-source/` workspace is created on each run.
The driver runs exactly `dune build @install` there with `DUNE_CACHE=disabled`
and `DUNE_ROOT` set to that fresh workspace. Explicit `DUNE_ROOT` is necessary:
otherwise Dune can select the enclosing checkout and interpret the nested path
as an unknown build context. The pinned Dune remains on the child `PATH`;
inherited Dune/Opam/OCaml overrides are removed. No existing checkout
`_build/default` binary is reused. Source and
lock hashes are checked before and after the build. Only the fresh workspace's
regular, executable `_build/default/bin/public_main.exe` is copied.

The result is `_build/public-cli/tree_of_md`: an independent **regular file**,
mode `0755`, published by a same-directory temporary file and atomic replacement.
`_build/install/default/bin/tree_of_md` is intentionally not used: Dune's install
entry is a symlink and the site consumer rejects symlink executable paths.
A successful repeat rebuilds from a fresh source workspace and atomically replaces
the prior regular binary; a failed build preserves the prior binary.

Preexisting symlink components, hardlinked files, source/output overlap, nonregular
or nonexecutable source binaries, unexpected entries in `public-cli/`, a leftover
source workspace and an existing driver lock are refused. Unrelated Dune build
artifacts are not read, changed or cleaned. Owned source staging/lock/temporary
files are removed on a handled failure; an interrupted process may leave an owned
workspace or lock, which a later run refuses rather than silently deleting.
A locally controlled isolated checkout is required; these checks do not promise
resistance to hostile concurrent replacement of directory ancestors.

## Output, failures and verification

On success, stdout is `CB_OK <actual-binary-sha256>` and the exit code is zero.
Failures print only a generic `CB_*` code, never source paths, compiler output,
input content or exception payloads. Arguments exit 2; build/refusal errors exit 1;
keyboard interruption prints `CB_INTERRUPTED` and exits 130 without a traceback.
Toolchain probing is bounded to 30 seconds, and the Dune build to 600 seconds.
Network downloads may be needed for Nix inputs and Dune's checksum-pinned sources;
this is a locked build, not a promise of an offline build.

Run the driver boundary tests using only the Python standard library:

```sh
python3 -B -m unittest discover -s test -p test_build_public_cli.py -v
```

Unit copy tests explicitly use synthetic bytes, never pretend to build a CLI and
never execute those bytes. They cover regular-copy publication, atomic repeat,
namespace refusal and stale-artifact/toolchain failure. Separately exercise the
real source-built executable with a reviewed public-only fixture:

```sh
_build/public-cli/tree_of_md --help=plain
_build/public-cli/tree_of_md --public-forest approved-public-v2.json --out-dir fresh-trees
```

Expect the help name `tree_of_md` and `PF_OK <root-count>`. Keep the output directory
fresh/empty and verify the generated trees. Neither a successful build nor a
passing synthetic fixture authorizes uploading real content.
